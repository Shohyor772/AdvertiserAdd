# Blogger Marketplace — учебный проект

Финальная учебная версия. Документация актуализирована 17.11.2026; единственная рабочая ветка проекта — [`main`](https://github.com/Shohyor772/AdvertiserAdd/tree/main). Временная ветка разработки удалена. Полный [указатель документации](docs/README.md), [задачи разработки](docs/development-tasks.md) и [план демонстрации по неделям](docs/weekly-submission-guide.md).

Самостоятельно запускаемая платформа для поиска блогеров и управления рекламными интеграциями. Использует React/Vite, Django REST API и существующую SQLite. Все основные сценарии выполняются локально: от регистрации и подбора до приёмки, отзыва и решения спора.

По уточнению пользователя **реальные деньги, внешние сервисы и подключения к платформам исключены**. Соцсети обозначают площадку профиля; статистика вводится вручную. Email подтверждается в интерфейсе, ИНН проверяется по формату/контрольной сумме, резерв/комиссия/возврат ведутся в учебном журнале. API внешних провайдеров заблокированы в учебном режиме даже при сохранённых ключах. Согласованный объём: [docs/educational-scope.md](docs/educational-scope.md).

## Запуск Windows

Требуются Python 3.14 и Node.js 22+. Существующая `db.sqlite3` сохраняется; миграции добавляют поля и таблицы. Не заменяйте уже настроенный `.env`.

```powershell
cd C:\AdvertiserAdd
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
# Только если .env ещё не существует:
Copy-Item .env.example .env
venv\Scripts\python.exe manage.py backup_database
venv\Scripts\python.exe manage.py migrate
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
venv\Scripts\python.exe manage.py collectstatic --noinput
venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Откройте http://127.0.0.1:8000/ . Для текущей учебной версии достаточно настроек:

```dotenv
DEBUG=true
EDUCATIONAL_MODE=true
LOCAL_MAINTENANCE=true
PAYMENT_MODE=test
```

Ключи Google/Telegram/DaData, SMTP, платёжный шлюз, Redis и Celery Worker для учебного запуска не нужны. Публичный хостинг/сертификаты не требуются. Учебный режим рассчитан на локальную демонстрацию; внешняя проверка ботов и банковские гарантии не заявляются.

## Тестовые аккаунты

В текущей пользовательской базе уже созданы `demo_brand1`–`demo_brand3`, `demo_blogger1`–`demo_blogger6` и модератор `demo_support`. Их пароль хранится локально в игнорируемом `tmp/demo-accounts.md`; он не публикуется в Git. Старые аккаунты и пароли не менялись. Подробности: [docs/manual-testing.md](docs/manual-testing.md).

Для новой чистой базы:

```powershell
venv\Scripts\python.exe manage.py seed_demo_accounts
```

Команда прекращает работу при совпадении логинов, не сбрасывает пароли и не создаёт сделки заранее. Для проверки сторон используйте разные браузеры/профили либо обычное и приватное окно.

## Что можно показать на защите

1. Зарегистрируйте рекламодателя или блогера. После регистрации нажмите «Подтвердить учебный email» прямо в приложении, затем войдите. Почтовый ящик открывать не нужно.
2. Блогер заполняет профиль, цены, аудиторию, запрещённые темы и автоответ. Локальная проверка показывает аномалии просмотров/ER и параметры аудитории без обращений к соцсетям.
3. Рекламодатель ищет по имени, площадке, тематике, городу, цене, подписчикам, полу/возрасту аудитории, сортирует по цене/подписчикам/рейтингу, сохраняет поиск или выгружает CSV.
4. Создаёт кампанию с датами, бюджетом и требованиями к аудитории. Система подбирает авторов, учитывает смежные темы и ограничения, сохраняет отклики. Из отклика или подобранного автора можно перейти к предложению с привязкой к кампании.
5. Отправляет текст или файл ТЗ и цену. Создаются чат, уведомление и автоответ. Стороны согласовывают встречную цену; свою последнюю цену принять нельзя.
6. Рекламодатель создаёт тестовый резерв. Блогер сдаёт HTTPS-ссылку (для демонстрации можно `https://example.test/post/1`; приложение не запрашивает содержимое внешней страницы).
7. Рекламодатель принимает работу или пишет замечания. После повторной сдачи выполняется приёмка, учитывается учебная комиссия, доступны взаимные отзывы и рейтинг.
8. Альтернатива: открыть спор с доказательствами. `demo_support` открывает сделку из сообщений/уведомлений, запрашивает материалы в чате и выносит обоснованное решение. Во время спора приёмка блокируется; учебная выплата/возврат выполняется однократно.
9. Модератор открывает раздел «Модерация»: обзор активности, поиск пользователей, блокировка/разблокировка, локальная проверка и подтверждение профилей, включение аналитики. Действия записываются в журнал; администраторские аккаунты защищены от изменения через эту панель.

Премиум-аналитика включается модератором без оплаты. Подтверждение профиля означает учебную модерацию, а не независимую проверку соцсетью. Внутренняя лента уведомлений работает без внешних push-сервисов; браузерные уведомления можно разрешить в профиле для открытого приложения.

## Автоматические задачи и данные

Локальный планировщик запускается автоматически вместе с `runserver` (в том числе без `--noreload`). Примерно раз в минуту проверяет:

- автоприёмку работ через 3 дня после последней сдачи, если нет спора или доработки;
- отложенный подбор к кампаниям и новые совпадения сохранённых поисков;
- локальные аномалии статистики;
- необходимость резервной копии текущих суток.

Первый цикл начинается примерно через 5 секунд. Работает, пока запущен сервер; после остановки приложения выполнение продолжится при следующем запуске. Никакие сроки пользовательских сделок искусственно не сокращаются.

Копии базы хранятся в `backups/`, отметка выполнения суточного backup — `backups/.local-backup-date`. Для ручного запуска:

```powershell
venv\Scripts\python.exe manage.py run_maintenance
venv\Scripts\python.exe manage.py backup_database
```

SQLite копируется через online backup с `integrity_check`. Файлы `media/` резервируйте отдельно. Для восстановления остановите приложение, сохраните текущую базу ещё одной копией, скопируйте выбранную проверенную SQLite из `backups/` в `db.sqlite3`, затем выполните миграции. Не заменяйте базу работающего сервера.

Приватные ТЗ и доказательства скачиваются через API с проверкой прав, а не через публичный `/media/`. Демо-данные, пароли, `.env`, backups и тестовые базы исключены из Git. Вывод фонового локального сервера — в `tmp/server.stdout.log`, ошибки — в `tmp/server.stderr.log`.

## Docker (необязательно)

При запущенном Docker Desktop и существующем `.env`:

```powershell
docker compose up --build -d
```

По умолчанию запускается только учебный web-контейнер с SQLite и встроенным планировщиком. База, материалы и backups подключены из папки проекта. Для нового клона предварительно создайте SQLite через локальный `manage.py migrate`. Остановка без удаления данных: `docker compose stop`. Не удаляйте volumes при обновлении.

PostgreSQL и Redis/Celery оставлены как необязательные архитектурные варианты (profiles `postgres` и `infrastructure`). Для учебной приёмки они не нужны; существующая SQLite автоматически на PostgreSQL не переключается. Docker-образ в учебном режиме запускает локальный Django server, в другом режиме сохраняет Gunicorn.

## Проверки и документация

```powershell
venv\Scripts\python.exe manage.py check
venv\Scripts\python.exe manage.py makemigrations --check --dry-run
venv\Scripts\python.exe manage.py test --noinput
venv\Scripts\python.exe manage.py spectacular --validate --fail-on-warn --file docs/openapi.yml
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
```

Браузерные тесты используют отдельную `tmp/e2e.sqlite3` и сами запускают сервер на 8002:

```powershell
venv\Scripts\python.exe scripts/prepare_e2e.py
venv\Scripts\python.exe manage.py collectstatic --noinput
cd frontend
npx.cmd playwright install chromium
npx.cmd playwright test
```

Пять сценариев покрывают автономную регистрацию, каталог/адаптивность, полный цикл сделки, арбитраж, кампанию/отклик/модерацию. В CI дополнительно проверяются PostgreSQL-конкурентность и сборка/healthcheck Docker. Результаты и ограничения: [docs/validation.md](docs/validation.md).

API: `/api/docs/`, `/api/schema/`; healthcheck: `/health/`. [Матрица требований](docs/requirements-audit.md), [UML/архитектура](docs/architecture.md), [статус проекта](project-status.md). Исходные лабораторные 1–4 сохранены без изменения в `docs/requirements/`.
