ВВЕДЕНИЕ
Цель работы: Изучение и получение навыков создания диаграммы компонентов и диаграммы последовательности.
Задачи:
Проанализировать архитектуру разрабатываемого сервиса для взаимодействия блогеров и рекламодателей.
Выделить основные компоненты системы и определить связи между ними.
Построить диаграмму компонентов в инструменте Draw.io.
Выбрать ключевой вариант использования («Безопасная сделка») и построить диаграмму последовательности.
Оформить отчёт с описанием проделанной работы и скриншотами диаграмм.

Выбор варианта использования для диаграммы последовательности
Для построения диаграммы последовательности был выбран ключевой вариант использования «Безопасная сделка» по следующим причинам:
Это основной бизнес-процесс сервиса, обеспечивающий гарантии для обеих сторон
В сценарии участвуют несколько объектов: рекламодатель, Frontend, Backend, платежный шлюз, блогер
Присутствуют как синхронные, так и асинхронные вызовы (Webhook)
Сценарий наглядно демонстрирует временную последовательность взаимодействий
Описание основного сценария «Безопасная сделка» (успешная оплата):
Рекламодатель нажимает кнопку «Оплатить безопасную сделку»
Frontend отправляет запрос на создание платежа в Backend
Backend создаёт платёж в платежном шлюзе и получает ссылку на оплату
Backend возвращает ссылку во Frontend
Frontend перенаправляет рекламодателя на страницу платежного шлюза

Платежный шлюз обрабатывает платёж
Платежный шлюз отправляет Webhook-уведомление в Backend об успешной оплате
Backend замораживает деньги на счёте сервиса и меняет статус сделки на «В работе»
Backend уведомляет Frontend об изменении статуса
Frontend отправляет push-уведомление блогеру

Инструменты реализации:
Для построения диаграмм использовался онлайн-редактор Draw.io (diagrams.net).
Причины выбора:
Бесплатное и кроссплатформенное решение
Наличие готовых шаблонов UML (Component Diagram, Sequence Diagram)
Возможность экспорта в PNG, PDF и векторные форматы
Интуитивно понятный интерфейс
Настройки для диаграммы последовательности:
Тип стрелки для синхронного вызова — закрашенный треугольник (Block)
Тип стрелки для возврата — пунктир с открытой стрелкой
Тип стрелки для Webhook — пунктир с закрашенным треугольником
Линии жизни (Lifeline) — прямоугольник с именем объекта + вертикальная пунктирная линия
Ответы на контрольные вопросы
1. Для чего создается диаграмма последовательности?
Ответ: Для моделирования временного порядка обмена сообщениями между объектами при выполнении одного варианта использования. Показывает, кто, кому, в какой последовательности и какие сообщения отправляет.
2. Скольким вариантам использования соответствует диаграмма последовательности?
Ответ: Одному варианту использования. Одна диаграмма последовательности описывает один сценарий (основной или альтернативный) одного варианта использования.
3. Что может выступать в качестве объектов на диаграмме последовательности?
Ответ: Акторы (пользователи), компоненты системы, классы, внешние системы, любые сущности, которые обмениваются сообщениями.
4. Для чего создается диаграмма компонентов?
Ответ: Для показа физической структуры системы: из каких компонентов (файлов, библиотек, модулей) она состоит и как они связаны между собой.
5. С помощью каких элементов на диаграмме можно показать классы объектов?
Ответ: Прямоугольником с именем класса и стереотипом <<class>> или просто именем класса. На диаграмме компонентов классы обычно показывают внутри компонентов или как отдельные элементы.
6. Как на диаграмме можно показать экземпляры классов объектов?
Ответ: Записью вида имя_объекта : Имя_Класса с подчеркиванием всей строки.
7. Что такое порт и для чего он нужен?
Ответ: Порт — это точка входа/выхода на границе компонента. Через порты компонент взаимодействует с внешним миром. Позволяет инкапсулировать внутреннюю структуру компонента.
8. Что такое линия жизни объекта и что она обозначает?
Ответ: Линия жизни — это вертикальная пунктирная линия, идущая вниз от объекта. Она обозначает время существования объекта в рамках диаграммы.
9. Как могут быть созданы объекты?
Ответ: Объекты могут быть созданы получением сообщения create (стрелка направлена к голове линии жизни) или существовать изначально.
10. Каким образом располагаются объекты в схеме и почему?
Ответ: Слева направо в порядке инициации взаимодействия. Самый левый — объект, который начинает взаимодействие (обычно актор). Это делает диаграмму более читаемой.
11. Что такое коннектор и какими виды связей предполагаются к использованию в коннекторах?
Ответ: Коннектор — это связь между портами или частями компонента. Может быть простой ассоциацией (сплошная линия) или временной связью (пунктир).
12. Что такое временная шкала для чего она нужна и как она располагается на схеме?
Ответ: Временная шкала на диаграмме последовательности располагается вертикально (сверху вниз). Начало схемы — начало взаимодействия, конец — завершение. Нужна для показа последовательности событий во времени.
Вывод
Диаграмма компонентов позволяет наглядно представить архитектуру системы и зависимости между её частями. Диаграмма последовательности детализирует один вариант использования, показывая точную последовательность вызовов. Вместе они дают полное представление о структуре и динамике системы.
