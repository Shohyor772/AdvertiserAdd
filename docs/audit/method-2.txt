Недели 6–10. Основная функциональность 
Цель работы 
На данном этапе выполняется переход от отдельных работающих 
компонентов к реализации основной функциональности мини-проекта. 
Необходимо объединить ранее созданные компоненты, реализовать 
недостающие функции и обеспечить выполнение основных 
пользовательских сценариев, определяющих назначение системы. 
К завершению этапа проект должен решать свою основную задачу, 
даже если часть дополнительных возможностей еще не реализована. 
Порядок выполнения 
На основании технического задания и результатов предыдущего 
этапа необходимо определить, какие части основных пользовательских 
сценариев уже реализованы, а какие требуют доработки. 
Дальнейшая работа включает: 
• реализацию недостающих функций, необходимых для выполнения 
основной задачи проекта; 
• организацию взаимодействия ранее созданных компонентов; 
• проверку выполнения основных пользовательских сценариев от 
начала до конца; 
• сопоставление реализованной функциональности с требованиями 
технического задания; 
• фиксацию требований, реализация которых переносится на 
следующий этап. 
При использовании инструментов искусственного интеллекта особое 
внимание следует уделять анализу взаимодействия компонентов, поиску 
причин ошибок и проверке предлагаемых решений. ИИ может помочь 
выявить недостающие части сценария, предложить способы интегр ации и 
подготовить тестовые данные. 
Полученные решения необходимо проверять в составе работающего 
проекта. Успешная работа отдельного компонента не гарантирует 
корректного выполнения пользовательского сценария в целом. 
 
Выходной продукт этапа 
Результатом работы является работоспособная версия мини-проекта, 
выполняющая его основную задачу. 
К завершению этапа должны быть: 
1. реализованы основные функции, необходимые для решения 
заявленной задачи; 
2. обеспечено взаимодействие компонентов в рамках основных 
пользовательских сценариев; 
3. получены проверяемые результаты выполнения этих сценариев; 
4. зафиксированы реализованные и оставшиеся требования 
технического задания; 
5. актуальное рабочее состояние проекта размещено в репозитории. 
Дополнительные функции, второстепенные сценарии и 
окончательная доработка отдельных компонентов могут выполняться на 
следующем этапе. 
Пример 
Для приложения записи студентов на консультации на предыдущем 
этапе были реализованы получение и отображение списка доступных 
консультаций. 
Теперь необходимо обеспечить выполнение основного сценария: 
просмотр консультаций >> выбор времени >> запись >> сохранение 
данных >> отображение результата. 
Для этого реализуются недостающие операции создания записи, 
проверки доступности выбранного времени и сохранения результата. 
При возникновении проблем взаимодействия клиентской и серверной 
частей ИИ может использоваться для анализа передаваемых данных, 
проверки API и поиска причин ошибок. Предложенные изменения 
проверяются на работающем приложении. 
К завершению этапа студент должен иметь возможность записаться 
на доступную консультацию и убедиться, что запись сохранена. 
Оставшиеся функции, например уведомления или дополнительные 
возможности управления консультациями, могут быть реализованы 
позднее, если они не являются необходимыми для выполнения основного 
сценария. 
Самопроверка 
Этап может считаться завершенным, если: 
• система выполняет основную задачу, заявленную в техническом 
задании; 
• основной пользовательский сценарий выполняется от начала до 
конца; 
• необходимые компоненты работают совместно; 
• результат выполнения сценария соответствует ожидаемому; 
• демонстрация не требует ручной подмены программных операций; 
• определено, какие требования реализованы, а какие остаются для 
следующего этапа. 
Критерии проверки пользовательского сценария 
Основной пользовательский сценарий считается реализованным, если: 
1. Определены начальные условия.  Понятно, какие данные и 
состояние системы необходимы для выполнения сценария. 
2. Сценарий выполняется полностью.  Предусмотренная 
последовательность действий проходит от начала до получения 
конечного результата без ручной подмены программных операций. 
3. Получен ожидаемый результат. Поведение системы соответствует 
требованиям технического задания, а не только внешне выглядит 
корректным. 
4. Результат подтверждается.  Изменения данных или состояния 
системы можно проверить независимо от сообщения об успешном 
выполнении операции. 
5. Соблюдаются существенные ограничения.  Система не допускает 
действий, которые делают основной сценарий некорректным, 
например повторного бронирования уже занятого времени. 
6. Сценарий воспроизводим.  При повторном выполнении с 
подходящими исходными данными система демонстрирует 
ожидаемое поведение. 
Пример проверки сценария записи на консультацию 
Исходные условия: в системе имеется консультация с одним свободным 
местом. 
• Выбирается доступная консультация и выполняется запись. 
• Система подтверждает создание записи. 
• В хранилище появляется соответствующая запись. 
• Количество доступных мест уменьшается. 
• Повторная попытка занять последнее место отклоняется. 
Проверка считается успешной, если все ожидаемые результаты 
подтверждены фактическим поведением системы. 
Материалы, предъявляемые на проверку 
На проверку представляются: 
• репозиторий с актуальной версией проекта; 
• запускаемая версия приложения; 
• демонстрация основных пользовательских сценариев; 
• краткий перечень требований технического задания с указанием 
состояния их реализации. 
Проверка предполагает демонстрацию выполнения основной задачи 
проекта и сопоставление полученного результата с требованиями 
технического задания.
