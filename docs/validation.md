## Сквозные проверки браузера

1. Регистрация → локальная кнопка подтверждения email → подтверждение → вход. Отслежены все запросы страницы: внешних запросов нет.
2. Каталог → ценовой фильтр → пустая выдача → сброс → профиль; проверены адаптивность и отсутствие ошибок JavaScript.
3. Рекламодатель и блогер в независимых browser context: предложение → встречная цена → согласование → тестовый резерв → сдача → доработка → повторная сдача → приёмка → взаимные отзывы.
4. Файл ТЗ без текста → согласование → резерв → публикация → спор с доказательствами → сообщение поддержки → обоснованное решение → тестовый возврат. Приёмка во время спора недоступна.
5. Кампания → автоматический подбор → отклик → перезагрузка с сохранением отклика → предложение с выбранной кампанией; панель модерации → подтверждение профиля → блокировка → разблокировка → снятие подтверждения.

Осмотрены снимки каталога на широком/мобильном экране, завершённой сделки, арбитража и панели модерации. Локальные артефакты в `tmp/`, отчёт `tmp/playwright-report`; в Git они не включены.

## Серверные проверки безопасности и состояний

Проверены роли и изоляция объектов, приватное скачивание файлов, положительные цены, текст или файл ТЗ, диапазоны поиска, невозможность принять свою последнюю цену, повторные резервы/приёмка/решение спора/отзывы, допустимые переходы, комиссия, запрет приёмки во время спора, трёхдневный срок автоприёмки, рейтинг и низкие оценки.

Новые учебные проверки подтверждают:

- даже при настроенных Google/Telegram/DaData ключах регистрация не обращается к сети и не отправляет SMTP-письмо;
- социальные endpoints отключены в учебном режиме;
- формат и контрольная сумма ИНН проверяются локально, без ложной отметки проверки реестром;
- модерация доступна только staff, администраторские аккаунты защищены;
- блокировку невозможно снять старой email-ссылкой;
- локальная проверка помечает аномалии и уведомляет один раз при переходе в подозрительное состояние; автоматически не назначает верификацию;
- модератор управляет премиум-доступом, обычный пользователь не может назначить его себе;
- возрастные требования кампании учитываются, отклики уникальны и сохраняются в базе;
- сохранённые поиски уведомляют только о новых совпадениях;
- планировщик вызывает автоприёмку и подбор, создаёт одну резервную копию на сутки;
- документация API использует локальные статические ресурсы Swagger.

Старые адаптеры OAuth остаются покрыты mock-тестами при явно выключенном учебном режиме. Это тесты кода, а не реальные обращения к платформам.

## Производительность и границы

Ранее воспроизводимый локальный замер с 5 000 профилями и 30 последовательными запросами через Django test client дал среднее 15,26 мс, p95 17,36 мс, максимум 24,19 мс (`catalog-benchmark.json`). Это серверный in-process замер, а не доказательство 50 000 одновременных пользователей или SLA.

Публичный production-SLA, реальные банковские операции, сторонняя верификация аудитории, доставка Web Push при закрытом приложении и реальные социальные подключения исключены пользователем.
