## Сквозные сценарии браузера

1. Каталог на десктопе/мобильном экране → фильтр по цене → пустая выдача → сброс → карточка автора. Проверяются ошибки JavaScript и горизонтальное переполнение.
2. Вход рекламодателя → предложение → вход блогера в отдельном browser context → встречная цена → согласие рекламодателя → тестовый резерв → сдача → доработка → повторная сдача → приёмка → взаимные отзывы.
3. Файл ТЗ без текста → согласование → тестовый резерв → публикация → спор с файлом доказательств → вход администратора → сообщение с запросом материалов → решение и тестовый возврат. Во время спора кнопка приёмки отсутствует.

Скриншоты осмотрены: каталог 1440 px и 390 px, завершённая сделка, арбитраж. Артефакты локально в `tmp/`, отчёт Playwright — `tmp/playwright-report`. Они не содержат реальных пользователей и не включены в Git.

## Серверные проверки

- Регистрация с хешированием пароля, подтверждением email и JWT; неверный ИНН и попытка регистрации администратором отклоняются.
- Повторная email-ссылка не разблокирует аккаунт, ранее заблокированный администратором.
- Неверные диапазоны/нечисловые фильтры дают 400; отсутствие совпадений возвращает пустую страницу.
- Предложение требует авторизации, роли рекламодателя, положительной цены, текста или файла. Отправитель берётся из request.user.
- Чужие переписки, сообщения и приватные файлы недоступны. Блогер не может назначить себе is_verified, is_staff и is_premium.
- Свою последнюю цену нельзя подтвердить; после согласования повторные переговоры закрыты.
- Оплатить может только рекламодатель сделки; повторная оплата не создаёт второй резерв; отключённый платёжный режим ничего не резервирует.
- Повторная приёмка не создаёт повторную выплату; учтена комиссия. Отзывы допускаются только после завершения и один раз от каждой стороны.
- Доработка требует причины и повторной сдачи; небезопасные ссылки отклоняются.
- Спор блокирует приёмку/автоприёмку; решение принимает только администратор; повторное решение невозможно.
- Автоприёмка не выполняется до истечения трёх дней.
- Мэтчинг учитывает тему/смежные темы, бюджет и ограничения; повторный запуск не дублирует подбор.
- Эвристическая аномалия помечается подозрительной, самозаявленные данные не получают автоматическую верификацию.
- Google OAuth: state, PKCE, CSRF, одноразовый обмен, отсутствие автоматического объединения по совпавшему email.
- Telegram: HMAC-подпись, временная метка, одноразовый nonce.
- Ошибка YouTube сохраняет аккаунт; суммарные просмотры канала не выдаются за средние просмотры публикации.
- CSV учитывает фильтр и экранирует формулы; приватные email в выгрузку не попадают.
- Параллельные истёкшие JWT-запросы клиента выполняют один refresh и сохраняют новый refresh token.

## Производительность

`scripts/benchmark_catalog.py` создаёт отдельную базу с 5 000 профилями, выполняет 3 прогрева и 30 последовательных запросов каталога с фильтрами и сортировкой по рейтингу через Django test client. Локальный результат: среднее 15,26 мс, p95 17,36 мс, максимум 24,19 мс. Машиночитаемый результат: `catalog-benchmark.json`.

Это измерение серверной обработки без реального HTTP, браузера, внешних API и конкурентных пользователей. Оно не доказывает SLA 99,5%, 50 000 активных пользователей, полноценный нагрузочный профиль или сетевую загрузку каталога за 3 секунды.

## GitHub Actions

CI содержит SQLite, PostgreSQL (включая два теста конкурентных резервов/выплат), клиентские тесты, сборку React, три браузерных сценария, проверку OpenAPI и сборку/healthcheck Docker.

Фактически завершённый [запуск 43850756214](https://github.com/Shohyor772/AdvertiserAdd/actions/runs/43850756214) для коммита `91bbb11` успешен во всех четырёх заданиях:

- `backend (sqlite)`: проверки, 24 теста + 2 ожидаемых skip, OpenAPI.
- `backend (postgres)`: все 26 тестов, включая конкурентную оплату/приёмку, миграции, OpenAPI.
- `browser`: клиентские тесты, React build и 3 Playwright-сценария.
- `docker`: образ собран, контейнер запущен, HTTP healthcheck пройден.

Первый запуск выявил ошибку кавычек аргумента Docker healthcheck PostgreSQL; она исправлена отдельным коммитом и подтверждена повторным успешным прогоном. Production-окружение этим не развёрнуто; Compose-стек с Redis/worker/beat целиком локально не запускался из-за выключенного Docker Engine.

## Что ещё не проверено/не завершено

Реальные OAuth-аккаунты и consent/scopes, SMTP-доставка, запросы реестра ИНН, реальный платёжный шлюз/webhook/выплаты/возвраты, статистика Telegram/TikTok, полноценный антифрод, Web Push вне открытой вкладки, продуктивный TLS, SLA и нагрузка. Эти пункты требуют внешних настроек и/или отдельной реализации. Успешные локальные тесты не закрывают их автоматически.
